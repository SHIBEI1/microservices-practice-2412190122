# 项目提案

## 项目名称

宠物医院管理系统

## 目标用户

- 宠物主人：维护个人及宠物信息，提交和查看就诊预约，查询病历与账单。
- 宠物医生：查看排班和预约信息，接诊宠物并记录诊疗情况。
- 医院管理员：维护医生、科室和排班信息，管理预约、病历和收费账单。

## 优先实现的业务场景

优先规划“宠物就诊预约”场景。宠物主人选择名下宠物、医生和就诊时间后提交预约；系统根据医生的接诊状态和排班信息进行校验，并记录预约的待确认、已确认、已完成或已取消等状态。该场景能够作为后续接诊、病历和收费流程的基础。

## 两个核心模型

### Pet

宠物模型用于记录宠物编号、名称、种类、年龄、所属主人和健康备注等信息。宠物是预约、病历等业务数据关联的基础对象。

### Appointment

预约模型用于记录预约编号、关联宠物、关联医生、预约时间、预约状态和预约备注等信息。预约状态需要支持待确认、已确认、已完成和已取消等流转。

## 第四周工作

### 本周实现的核心业务流程

本周在第三周 Spring Boot 工程的基础上，实现“宠物就诊预约”业务流程。首先建立宠物档案，登记医生信息及每周出诊时间；然后选择宠物、医生和预约时间提交预约。系统检查医生是否接诊、预约是否符合出诊安排以及时段是否存在冲突，通过检查后保存待确认的预约记录。

预约可以由待确认变为已确认，已确认的预约在到达就诊时间后可以完成。待确认或已确认的预约可以在就诊时间前取消，取消后保留原有记录并释放该时段，允许重新预约。

### 参与流程的业务实体及其关系

1. `Pet`：宠物实体，记录名称、种类、年龄、主人姓名、联系电话和健康备注。一个宠物可以拥有多条预约记录。
2. `Appointment`：预约实体，记录关联宠物、关联医生、预约时间、就诊原因、创建时间及预约状态。每条预约必须属于一个已经存在的宠物，并关联一名已经存在的医生。
3. `Doctor`：医生实体，记录医生工号、姓名、科室、出诊星期、出诊起止时间和接诊状态。一名医生可以接收多条预约，医生的出诊安排用于判断预约时间是否有效。

本周两个核心实体为 `Pet` 和 `Appointment`，二者为一对多关系；`Doctor` 是预约流程的支撑实体，与 `Appointment` 同样为一对多关系。预约通过 `pet_id`、`doctor_id` 分别关联宠物和医生。

### 需要在 Service 中检查的业务规则

本周重点检查“同一医生在同一时段不能接收两条有效预约”的规则。每次就诊占用 30 分钟，预约时间必须为整点或半点。`AppointmentService` 在创建预约时先查询医生对应时段是否已被占用；如果已经占用，则拒绝创建并返回 `409 Conflict`，避免出现重复预约。

此外，Service 还会检查宠物和医生是否存在、医生是否接诊、预约是否为未来时间、完整就诊时段是否落在出诊安排内，以及同一宠物是否已有同时段预约。确认、完成和取消操作也在 Service 中检查当前状态，保证预约按照允许的流程变化。

### 本周实现范围

业务代码继续放在 `monolith/` 工程中，沿用 `com.zjgsu.kl` 基础包，按实体、Repository、Service、DTO、Controller 和异常处理分层。通过 REST 接口操作宠物、医生和预约，使用 JPA Repository 和 H2 文件数据库保存数据，并编写业务规则及持久化测试。数据库设计记录在 `docs/database.md`，运行命令、验证结果和截图位置记录在 `docs/homework/week-04/index.md`。
